# Mihomo 代理（飞牛 fnOS 应用）

在飞牛 NAS 上运行 Mihomo 内核的本地代理应用。装好后桌面有图标，点开就是管理面板：
加订阅、用成熟的面板管节点、看流量日志，还能让 NAS 自己的出站流量（下载中心、Docker 拉镜像、系统更新）
也走代理。

源码：<https://github.com/fangfuzha/fnOS-Mihomo>（MIT 许可；应用包内分发的第三方组件许可见文末）。

## 它能做什么

- **订阅管理**：填一条订阅链接，自动解析成节点列表。支持机场常见的 base64 链接列表订阅，
  也支持机场直接给出的完整 Clash 配置（节点、策略组、分流规则全部采用机场自己的）。
- **控制面板**：内置 MetaCubeXD / zashboard / Yacd 三种成熟面板，在线一键切换；
  节点切换、策略组、连接查看、流量统计都交给面板，本面板只保留必要内容。
- **随订阅自动启停**：订阅里有可用节点就自动启动内核，没有就自动停掉，不用手动开关。
- **本机代理**：mixed 端口同时提供 HTTP 与 SOCKS5，浏览器、终端都能直接用。
- **NAS 本机走代理**：让 NAS 自身的出站流量经过代理内核，按分流规则国内直连、国外走代理。
  下载中心、Docker 拉镜像、网盘同步、系统更新都受益。
- **分流**：国内直连、国外走代理，局域网地址永远直连（NAS 自己的服务不会被绕进代理）。
- **离线可用**：GeoIP / GeoSite 数据随应用包一起安装，不依赖联网下载。

## 安装

### 方式一：FnDepot 应用源（推荐，能自动升级）

1. NAS 上装好 **FnDepot**（飞牛 NAS 上的第三方应用管理器）。
2. 在 FnDepot 里添加应用源，填：`https://github.com/fangfuzha/FnDepot`
3. 刷新应用列表，找到「Mihomo 代理」点安装。

源里的版本号每次发版都会更新，FnDepot 会提示有新版本，装完也能在它里面直接升级。

### 方式二：手动安装

1. 在飞牛桌面打开 **应用中心 → 手动安装**。
2. 上传对应的安装包（Release 里的 `Mihomo-<版本>-x86.fpk` / `Mihomo-<版本>-arm64.fpk`）：
   - x86 包（Intel / AMD 处理器）
   - arm64 包（ARM 处理器，如飞牛 ARM 盒子）
3. 按安装向导填写。**订阅链接留空也行**，装好后到面板里添加更方便。
4. 装好后桌面会出现「Mihomo 代理」图标，点开进入面板。

> 不知道自己的 NAS 是哪个架构？在 SSH 里执行 `uname -m`：
>> 输出 `x86_64` 用 x86 包，输出 `aarch64` 用 arm64 包。

## 使用

### 第一步：添加订阅

打开面板 → 「订阅管理」→ 填入订阅链接 → 点「保存并拉取」。
拉到节点后，列表里会显示节点数量。

### 第二步：确认内核已启动

订阅拉到节点后，内核会自动启动，面板顶部显示「内核状态：运行中」即可。
没有可用节点时内核会自动停止；也可以在「基础设置」里手动启动 / 停止 / 重启。
手动停止之后，自动启停不会再来拉起它，直到你手动启动一次为止。

### 第三步：设置代理

在「基础设置」里可以看到代理端口（默认 7890）。

- **本机使用**：在浏览器或系统里把代理设为 `NAS地址:7890`（HTTP 和 SOCKS5 都支持）。
- **局域网使用**：勾选「允许局域网设备使用本机代理端口」，其它设备填 `NAS地址:7890` 即可。

### 第四步（可选）：让 NAS 自己也走代理

左侧导航选「NAS 本机走代理」→ 拨动开关 → 点「应用」。

开启之后：

- NAS 自己的出站流量（下载中心、Docker 拉镜像、网盘同步、系统更新）会经过代理内核，
  按机场的分流规则决定直连还是走代理 —— 国内站点仍然直连，不会绕一圈。
- **只影响 NAS 自己**，局域网里其它设备的网络访问完全不受影响，
  客户端不需要改网关设置。
- 关闭时立刻恢复，NAS 会自己创建并删除一个叫 `Mihomo0` 的虚拟网卡。

> **安全设计**：开启后应用会验证接管是否真的生效。如果 TUN 没起来或内核异常，
>> 会自动撤销接管并提示失败，不会让 NAS 陷入上不了网的半死状态。

### 第五步（可选）：给面板加访问密码

面板默认**不需要密码**：同网段任何设备打开 `NAS地址:8765` 都能直接用。
不想让别人动你的订阅和设置，就去「基础设置 → 面板访问」设一个用户名和密码。

- 设了密码之后，除了登录接口以外的所有接口都要先登录，
  订阅链接不会再被同网段直接读到（内核控制口是另一层，见上面的控制端口密钥）；
- 口令只以 PBKDF2 哈希的形式存在本机配置文件里，**明文不落盘**；
- 连续输错 5 次会锁 1 分钟；
- 改过密码或清除密码后需要重新登录；
- 面板重启（热更新、升级应用）后也要重新登录一次。

> 忘记密码没有找回入口 —— 本机不保存明文，只能清除密码后重新设置。

## 面板说明

面板左侧是导航栏，右侧是当前页面的内容。

| 导航项 | 内容 |
|---|---|
| 运行状态 | 内核状态、运行时长、版本、代理端口、订阅数量、本机接管状态一览 |
| 订阅管理 | 添加、启用/停用、更新、删除订阅；显示节点数量与最近更新时间 |
| 控制面板 | 选择第三方面板（MetaCubeXD / zashboard / Yacd，可随时切换），点「打开控制面板」在新标签页使用；本机有全球 IPv6 时还多一个「用 IPv6 打开」的快捷入口；节点切换、策略组、流量统计都在面板里 |
| NAS 本机走代理 | 开关本机出站流量接管 |
| 基础设置 | 代理端口、控制端口与密钥（首次安装自动生成）、运行模式、分流策略、是否允许局域网访问、是否启用 IPv6 代理、面板访问用户名与密码、启动 / 停止 / 重启内核 |
| 运行日志 | 内核日志表格，按级别着色，可按级别筛选、可调显示行数，排障用 |

> 订阅列表支持按名称或链接搜索，也可以切换列表 / 卡片两种视图；
> 页面右侧的滚动条是面板自己画的，样式跟主题一致，不受浏览器深浅色设置影响。

> **控制端口密钥在首次安装时自动生成**：控制口（默认 9090）绑在所有网卡上，
> 没有密钥的话，同网段任何设备都能直接读走节点凭据、改内核配置。
> 密钥不用你操心，面板生成的第三方面板地址会自动带上它。
> 在「基础设置」里把它清空，内核接口就变成不校验密钥 —— 能用，但不建议。
>
> **面板文件从哪来**：面板随应用包一起分发，装好就有本地那份，
> 直接解压到 NAS 本机（`/vol1/@appdata/Mihomo/ui/`），由内核在 `9090` 端口的 `/ui/` 下提供，
> 局域网里用浏览器直接访问即可。
>
> 只有本地那份缺失、或上游出了新版本时才会去 GitHub 重新下载
> （新版本会缓存在 `/vol1/@appdata/Mihomo/cache/dashboards/`）。
> 探测不到上游（断网或 GitHub 不通）时会继续用本地那份，不影响使用。

## 常见问题

**控制面板页一直显示「正在下载」或下载失败**

面板文件随应用包分发，正常情况下不需要下载。出现这个提示说明本地那份缺了，
或者上游出了新版本、正在拉新版。

国内网络直连 GitHub 常常不稳定，应用会自己重试几次；
实在拉不下来时会继续用本地已有的那份（如果还在）。
也可以过一会儿重新进入「控制面板」页，下载状态会自动刷新；
或者在 NAS 上重新安装应用包。

**面板要不要设访问密码？**

默认不用 —— 面板就在 8765 端口上，开着就是同网段可见。
内网自用觉得麻烦可以不管；介意的话去「基础设置 → 面板访问」设一个即可，
设完之后订阅链接与控制密钥就不会再被同网段直接读到了。

**订阅拉取失败 / 节点数为 0**

先在「运行日志」里看有没有拉取错误信息。应用启动时会自动重试一次空订阅，
也可以在「订阅管理」里手动点「更新」。

**内核启动失败，日志提示找不到 GeoIP 数据**

这是包内文件损坏或架构不匹配，重新安装对应的安装包即可。

**代理连不上，但节点延迟测试是通的**

说明内核和节点都正常，问题在分流规则上。可以在「基础设置」里把运行模式
临时改成「全局模式」，如果全局能通，就是规则匹配的问题。

**开了代理，ping 某个网站还是不通**

`ping` 走的是 ICMP，代理节点不转发 ICMP，所以 ping 不通**不代表代理没生效**。
判断代理是否正常请用 TCP 请求，比如 `curl -I https://example.com` ——
能返回状态码就说明链路是通的。

另外「基础设置」里的「启用 IPv6 代理」默认开着：
开启后 IPv6 流量也会被 TUN 接管（DNS 查询同样），
不用时可以关掉。

**开启「NAS 本机走代理」后 NAS 上不了网**

应用会自动检测并回滚，NAS 应该已经恢复正常。如果仍有问题：
在「运行日志」里看内核报错；确认 `/dev/net/tun` 存在；
也可以直接关掉该开关，代理端口 7890 仍然可用。

**怎么确认本机接管生效了**

在 NAS 的 SSH 里执行 `curl http://ip-api.com`，如果显示的 IP 和关闭接管时不同，
就说明流量确实走了代理节点。也可以执行 `ip addr show Mihomo0`，
设备存在就代表接管已生效。

## 卸载

在应用中心卸载即可。卸载时会问是否保留订阅与配置：

- **保留**：重新安装后订阅还在。
- **一并删除**：订阅、节点缓存、配置全部清掉。

TUN 虚拟网卡随内核进程一起消失，卸载后不留任何痕迹。

## 端口说明

| 端口 | 用途 |
|---|---|
| 8765 | 面板 Web 界面 |
| 7890 | 代理端口（HTTP + SOCKS5） |
| 9090 | Mihomo 控制接口（同端口下的 `/ui/` 是控制面板页面） |

改端口时注意：面板端口 8765 在 `manifest`、`app/ui/config` 和 `cmd/main` 三处写死，
要改得三处一起改，否则飞牛桌面入口会打不开。

**IPv6**：面板（8765）和控制接口（9090）都同时监听 IPv4 和 IPv6，
用 `http://[2409::xxxx]:8765/` 这样的地址进面板一样能用。
「控制面板」页生成的第三方面板地址会跟着你实际用的地址走，
IPv6 地址会自动带上方括号（`http://[2409::xxxx]:9090/ui/...`），不用手工改。
页面上还有一个「用 IPv6 打开」按钮，会用本机的全球 IPv6 地址打开面板；
信息卡里也把本机的 IPv6 地址列了出来，点哪个地址就用哪个打开。
代理端口（7890）要开了「允许局域网设备连接代理端口」才会对外监听，那时它同样是双栈的。
